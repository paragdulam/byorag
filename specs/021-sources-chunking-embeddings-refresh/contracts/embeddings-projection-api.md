# Contract: Embedding Projection API (one new endpoint, one behavior change)

No authentication (single local user), matching every existing endpoint in this project. Additive
to `014-vector-view-screen`'s `contracts/vector-view-api.md` — the `GET
/api/embeddings/projection-methods` response shape is unchanged; only the `available` values for
`umap`/`pca` flip from `false` to `true` once this feature ships.

---

## `GET /api/embeddings/projection-methods` (behavior change only, no shape change)

**Response**: `200 OK`:

```json
{
  "methods": [
    { "id": "vector", "label": "Vector", "available": true },
    { "id": "umap", "label": "UMAP", "available": true },
    { "id": "pca", "label": "PCA", "available": true }
  ]
}
```

- `umap` and `pca` now report `available: true` (previously `false`, per `014-vector-view-screen`).
  No other change to this endpoint.

---

## `POST /api/embeddings/project` (new)

Computes a 2D projection (UMAP or PCA) over a caller-supplied set of already-saved chunk embeddings
— for either a single document's chunks or an entire corpus's chunks combined (spec FR-014–FR-018).
The caller (frontend) is responsible for first fetching the relevant `SavedEmbedding` rows via the
existing `GET /api/embeddings/saved?chunkId=` per chunk, and assembling the request body below.

**Request body**: `application/json`

```json
{
  "method": "umap",
  "entries": [
    { "chunkId": "c1", "documentId": "d1", "vector": [0.0123, -0.0456, "... "] },
    { "chunkId": "c2", "documentId": "d1", "vector": [0.0201, -0.0333, "... "] }
  ]
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `method` | `"umap" \| "pca"` | yes | Must match one of the `available: true` methods from `GET /api/embeddings/projection-methods`. |
| `entries` | array | yes | One entry per embedded chunk in the requested scope (single document, or every embedded chunk across a corpus). |
| `entries[].chunkId` | string | yes | Echoed back on the corresponding output point. |
| `entries[].documentId` | string | yes | Echoed back on the corresponding output point; used by the frontend to color/group points by source document in "Entire Corpus" scope (FR-016). |
| `entries[].vector` | number[] | yes | A saved embedding vector (from `GET /api/embeddings/saved`). |

**Response**: `200 OK`, `application/json`:

```json
{
  "points": [
    { "chunkId": "c1", "documentId": "d1", "x": 1.223, "y": -0.87 },
    { "chunkId": "c2", "documentId": "d1", "x": 0.998, "y": -0.71 }
  ]
}
```

- `points` has exactly one entry per input `entries` row, in the same order.

**Error responses**:

- `422 Unprocessable Entity` — `{ "detail": "At least 5 embedded chunks are required to compute a projection; received {n}." }` — fewer than 5 entries submitted (spec FR-018; the frontend is expected to keep the projection selector disabled below this minimum, so this is a defensive server-side check, not the primary UX gate).
- `422 Unprocessable Entity` — `{ "detail": "All vectors must have the same dimension; received mixed dimensions." }` — entries mix vectors of different lengths (e.g., embeddings generated by two different models).
- `400 Bad Request` — `{ "detail": "Unknown or unavailable projection method '{method}'." }` — `method` is not one of the currently `available: true` methods.

## Unchanged

`GET /api/embeddings/models`, `GET /api/embeddings/generate/stream`, `GET
/api/embeddings/save/stream`, `GET /api/embeddings/saved`, and `GET /api/chunking/saved-chunks` are
untouched by this feature.
